# Seasonal + regional theme variants

> Issue: [#731](https://github.com/ArtemioPadilla/rastrum/issues/731). Epic
> [#720](https://github.com/ArtemioPadilla/rastrum/issues/720).

The site now subtly tints chrome accents and a homepage hero illustration to
reflect Mexico's ecological calendar — `monarca` (Oct–Mar), `lluvias` (Jun–Sep),
`secas` (Apr–May), and `default` (the brand emerald, used as a fallback for
non-MX users in v1).

This runbook explains how the seasonality logic resolves so it can be audited,
adjusted, or extended without spelunking the code.

## Where the logic lives

| File | Role |
|---|---|
| `src/lib/seasonal-theme.ts` | Source of truth — month → theme + region resolution. Pure / unit-tested. |
| `tests/unit/seasonal-theme.test.ts` | Pins the mapping. |
| `src/layouts/BaseLayout.astro` | Inline `<style is:global>` defining the CSS variables + an inline boot script that mirrors the lookup before first paint. |
| `src/components/SeasonalThemePicker.astro` | UI in Profile → Apariencia (Preferences tab). |
| `src/components/SeasonalAccent.astro` | Decorative emoji glyph driven by the `--rastrum-season-emoji` variable, dropped above the homepage hero title. |
| `tailwind.config.mjs` | Safelist for the `rastrum-season-*` classes — they are defined globally in BaseLayout's `<style>`, not generated by Tailwind. |

## Month → theme mapping (MX-Centro, v1)

| Month  | Theme     | Why |
|--------|-----------|-----|
| Jan    | `monarca` | Eastern monarchs are still overwintering in Michoacán/Edomex. |
| Feb    | `monarca` | " |
| Mar    | `monarca` | Late-March monarchs leave; theme sticks to keep the transition gentle. |
| Apr    | `secas`   | Peak of late dry season. |
| May    | `secas`   | Last dry month before the rains. |
| Jun    | `lluvias` | Rains start. |
| Jul    | `lluvias` | " |
| Aug    | `lluvias` | " |
| Sep    | `lluvias` | Rains end. |
| Oct    | `monarca` | Monarchs arrive at colonies. |
| Nov    | `monarca` | " |
| Dec    | `monarca` | " |

`MX-Norte` and `MX-Sur` fall back to the `MX-Centro` mapping for v1. We will
differentiate them in v1.1 once we wire eco-region data into
`recompute-user-stats`. Anything outside the MX prefix resolves to `default`.

## Resolution order (per page-load)

1. **Manual override** at `localStorage[rastrum.theme.seasonal]`. One of:
   - `'auto'` — defer to step 2 (default, also written when no value exists).
   - `'default'` / `'monarca'` / `'lluvias'` / `'secas'` — applied as-is.
2. **Auto pick** — `pickSeasonalTheme(now, region)`. `now` defaults to
   `new Date()`; `region` is `'MX-Centro'` for v1 (region inference from
   `country_code` is a v1.1 follow-up; today the picker is region-agnostic
   from the inline script's perspective).

The resolved theme is written as `data-season="<theme>"` on `<html>`. CSS
variables in `BaseLayout.astro` cascade per-attribute selector, so changing
the attribute is the *entire* paint cost — no full reload, no flicker.

## Manual override UI

Profile → Apariencia (Preferences tab) renders 5 buttons: Auto + the four
themes. Selecting a value writes `localStorage[rastrum.theme.seasonal]`,
and the picker calls `applySeasonalTheme()` immediately so the swap is
instant. The "currently applying" hint under the buttons surfaces what
`Auto` resolves to *right now* — handy for users wondering why their
chrome doesn't match their expectations.

## CSS variables exposed

| Variable | Purpose |
|---|---|
| `--rastrum-season-accent` | Primary tinted accent (e.g. orange-600 in monarca). |
| `--rastrum-season-accent-soft` | Soft tint for backgrounds. |
| `--rastrum-season-tint` | Translucent overlay (rgba) for hover/highlight. |
| `--rastrum-season-emoji` | Glyph used by `SeasonalAccent` (CSS `content`). |

Three utility classes are defined globally in BaseLayout's `<style is:global>`
and safelisted in `tailwind.config.mjs`:

- `.rastrum-season-accent` — `color`
- `.rastrum-season-accent-bg` — `background-color`
- `.rastrum-season-accent-border` — `border-color`
- `.rastrum-season-illustration` — emoji glyph via `::before`

## How to add a new season

1. Add the theme id to `SeasonalThemeId` in `src/lib/seasonal-theme.ts`.
2. Add a `:root[data-season='<id>']` block to BaseLayout's `<style is:global>`
   with the four CSS variables.
3. If the auto pick should ever surface this theme, extend
   `MX_CENTRO_BY_MONTH` (or add a new region map).
4. Add the i18n labels under `settings.preferences.season_<id>` in BOTH
   `src/i18n/en.json` and `src/i18n/es.json`.
5. Add the option to `SeasonalThemePicker.astro`'s `opts` array.
6. Update the inline boot script in `BaseLayout.astro` if (and only if)
   the new theme participates in the auto pick — it must stay in sync
   with `pickSeasonalTheme()`.
7. Add a row to the table above and bump the test in
   `tests/unit/seasonal-theme.test.ts`.

## Out of scope (v1)

- Per-illustrator themes / community-submitted themes.
- Sound themes.
- Eco-region-aware mapping (`MX-Norte` / `MX-Sur`) — currently fall back to
  `MX-Centro`. Differentiation tracked as a v1.1 follow-up; the registry
  shape already accepts new region keys.
- Server-side persistence — the override is localStorage-only. Cross-device
  sync via a `users.theme_pref` column is a v1.1 follow-up if user demand
  surfaces.
